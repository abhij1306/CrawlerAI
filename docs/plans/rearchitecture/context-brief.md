## What the feature branch got WRONG (avoid these)
Two competing architectures coexisting (tiered cascade + recipe-first cutover, unfinished). "Compiler that never publishes records" invariant violated: compile_recipe_candidate reverse-derived recipes from already-published records (hidden 2nd producer). LLM tier live-ineffective: 1/36 useful, 34/36 failed. One-rung escalation ladder dead-ended after browser. Failure classification lied (insufficient_input_bundle instead of listing_detection_failed).

## The 5 principles the architecture must satisfy (from branch review, adopt)
1. No brittle dependency on selector-based architecture.
2. LLM is a one-time setup cost; future crawls reuse the learned intelligence (compiled, grounded, replayed LLM-free).
3. Simple HTTP crawls work without LLMs (deterministic floors first).
4. The extraction/acquisition escalation loop is surface-agnostic (one ladder for commerce+jobs, listing+detail; extraction DECLARES capability needs, acquisition FULFILLS them; honest exhaustion, LLM as last rung to LEARN not to guess values).
5. A new surface = adding a typed schema (SurfaceSpec), not a new pipeline.
